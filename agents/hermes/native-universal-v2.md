# Hermes — Native Universal v2 Bootstrap

This is a role overlay, not an authority source. Use it only when `UNIVERSAL_V2_DEVELOPMENT` is active and Slack Controller–Executor mode has **not** been explicitly selected.

## Boot and binding

1. Load protected-base `AGENTS.md`, the active project profile, `core/node-architect/universal-runtime-default-profile.json` and exact native runtime contracts.
2. Resolve exact source SHA, current task/run, controller/executor entrypoints and current native checkpoint. Never reactivate a terminal Q0 Run.
3. Select required skills from canonical manifests and verified host configuration, not names or memory.
4. Independently verify each required skill's ID, absolute `SKILL.md` path, version, source digest, installed bytes SHA256, trigger, Hermes loader event, active session binding, task activation and observable application.
5. Report separate statuses for declared, installed, loaded, activated, applied and behavior verified. Source presence alone is not loader proof. Missing host/session evidence is `HERMES_NATIVE_LOAD_PROOF_UNAVAILABLE`, never PASS.
6. Keep `UR.G0..UR.G6` authoritative; do not import legacy GWC v1 or Slack MVP `WAIT_CONTROLLER` rules by default.
7. Read-only diagnosis and bounded non-effect preparation may continue when loader evidence is missing. Never admit an effect that depends on a missing binding, create receipts retrospectively or infer approval from this overlay.
8. Keep Human approval, native effect authority and Controller-managed runtime state separate. Preserve Q0 terminal identity and DWO isolation.

Return `BOOT_SOURCES`, `SKILL_DEPENDENCY_GRAPH`, `SKILL_BINDING`, `HERMES_NATIVE_LOAD_PROOF`, `CURRENT_RUN_CONTINUITY`, `CAPABILITY_DIFF`, BP-01..BP-08 and 21 canonical AC statuses, plus exact `NEXT_LEGAL_ACTION`.

After a source merge, read back the exact released main SHA and independently verify host skill loading in the **real Hermes session**; do not claim handoff consumption from a GitHub commit or Slack post alone.
